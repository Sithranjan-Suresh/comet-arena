# Failure-state audit (product_spec §5)

Every cell of the failure table, with the behavior observed in the code and the test that proves it. Run
`npm test` to re-verify; every referenced test runs in CI. ✅ = matches the spec. 🔧 = a mismatch the audit
found, fixed in the same pass.

## Other findings from the audit

- 🔧 The job runner now emails the admin for any failed scheduled job (`tests/job-runner.test.ts`), which several cells above rely on for "alert admin".
- Known gap: when an admin approves a queued submission, the original `submissions` row stays `queued` (the listing itself is correct). Cosmetic; the admin Submissions page shows it as queued until cleaned up.
